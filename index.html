Student project

I built an equity research app, then gave it a way to answer questions.

Market Lantern is a React Native app I have been building for quotes, charts, full financial statements, earnings, options, news, filings, trade disclosures, and macro calendars.

Behind it is a Convex backend that pulls from Financial Modeling Prep, Alpaca, and CNN on a schedule, and a small Python agent that answers questions using the same data. This page walks through all of it.

Figures in the mockups on this page are illustrative sample data, not live prices or results.

Search and discovery

Find a ticker even when it is not in my list yet.

Search first looks through the stock universe I seed into Convex. If nothing matches, it asks Alpaca's asset search, and the ticker gets saved for next time.

  • Fuzzy search over seeded stocks ranked by market cap, with an Alpaca fallback for anything missing
  • Recent searches stored per user
  • Curated sector lists (Financials, Technology, Energy, Consumer, Healthcare) refreshed by a monthly job
  • Symbols are normalized for case and for hyphen or dot share classes, so ms, Ms, and MS all land on the same page

The stock page

One screen per ticker, nine ways to read it.

Tapping any ticker opens the stock page. I wanted it to feel like a light terminal: price on top, a chart you can actually touch, then tabs in the order I research a name.

  • A live quote and bars from Alpaca, and a company profile from FMP that falls back to Alpaca when FMP is rate limited

  • Seven ranges from 1D to ALL, with open, high, low, and volume recalculated for the range you pick
  • Company info: sector, industry, exchange, CEO, employees, IPO date
  • Results are cached for 60 seconds on 1D and 5 minutes on longer ranges, and a stale copy is served if the vendor call fails

Fundamentals

The full statements, not three rows of them.

Most free apps show revenue and net income and stop. I pull the whole income statement, balance sheet, and cash flow statement and lay them out the way a 10-K does, with charts on top for the story.

  • Annual or quarterly periods for all three statements, cached in Convex per symbol and period
  • Charts for the margin waterfall, assets mix over time, cash position and change, uses of cash, and debt maturity mix
  • Metric drilldowns: tap a line item to see its history and a trend chart
  • FMP stable endpoints first, older v3 endpoints as a fallback, and a clear Premium Data state when the plan does not cover a symbol

Data pipeline

Fetch on a schedule, store once, read many times.

The phone almost never calls a data vendor directly. Convex actions fetch on a timer and write into tables, and the app subscribes to queries over those tables. That kept me inside the FMP plan's rate limits and made screens open fast.

How I kept it cheap and stable

a

Skip when the market is closed

The one minute price job reads the market status first and exits when the U.S. market is closed. Only the top 100 stocks by market cap are refreshed.

b

Write only what moved

Incoming prices are compared with what is stored, and a row is written only when the price or change actually moved. Writes go in batches of 100.

c

Cache first, stale on failure

Stock details check a shared apiCache table before calling Alpaca or FMP: 60 seconds for intraday, 5 minutes for longer ranges. If a fetch fails, the last good copy is returned.

d

A fallback for every vendor call

FMP stable endpoints fall back to v3, company profiles fall back from FMP to Alpaca, and insiders fall back to Form 4 filings. A 402 response marks the symbol as premium so the screen shows a message instead of crashing, and empty results are never cached.

The AI assistant

How a question moves through the agent.

The chat screen is labeled Market Lantern AI. It talks to a FastAPI service I run beside the app. The model only gets tools when the message looks like a data request.

01

You ask in the app

A question is typed in the chat, for example whether the market is open or who reports earnings today.

02

The screen posts it

The React Native client sends the message to the agent's /agent/chat endpoint and waits for a text reply.

03

Tools run if needed

Greetings are answered directly. Data questions can call market status, stock search, earnings, news, or a web search.

04

A reply comes back

Tool output is trimmed, the model writes a short answer, and the chat screen renders it as Markdown.

Guardrails I added after testing

Tools only when needed

A greeting check and a keyword check (price, earnings, news, ticker, and so on) decide whether the model even sees the tool list. Small talk goes out with tools turned off.

Recover sloppy tool calls

Some free models print a JSON tool call as plain text. The server parses it, maps a few unknown tool names to a web search, and runs it. XML style tool calls are refused.

Keep the context small

Each tool result is cut to 2,000 characters before it goes back to the model, and tool errors come back as data instead of crashing the request.

You are "Market Lantern AI", a professional financial assistant for Market Lantern customers. Speak directly to the user. Be helpful, polite, and professional. Do not output internal monologue. Use tools only when needed for data.

What I learned

Things I would tell myself at the start.

01

Rate limits shape the architecture

Vendor plans cap how often you can call them. Moving every fetch into scheduled jobs with a cache table is why the backend looks the way it does, and it is also why screens open quickly.

02

Real data is messy

Hyphen and dot tickers, filings dated in the future, empty responses that look like success, premium-only symbols. A lot of my code is normalizing and checking, not drawing screens.

03

Small models need guardrails

Free models drifted, invented tools, or narrated their thinking. Gating tools by intent, parsing stray tool calls, and trimming tool output helped more than swapping models.

04

Reuse one data path

The agent reads from the same Convex queries as the screens. With one source of truth, the assistant and the app do not disagree, and I fix a bug once.

Still on my list: watchlist and portfolio screens on top of the tables that already exist, conversation memory for the agent, and tests around the sync jobs.

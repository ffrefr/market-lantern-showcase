The research app

The work around a ticker, in one client.

I got tired of jumping between a quote, an earnings calendar, a news feed, and a filing. The app keeps those views on one stock screen, with tabs that match how I actually read a name.

  • 01 Quotes, historical bars, and an interactive line chart with 1D through ALL ranges
  • 02 Fundamentals, ratios, analyst estimates, and an analysis tab
  • 03 News, SEC filings, and Form 4 insider activity
  • 04 Congressional trade disclosures
  • 05 Earnings and economic calendars, movers, and a Fear and Greed index
  • 06 Watchlists, portfolios, and a small community layer
The assistant

How a question moves through the agent.

The chat screen is labeled Market Lantern AI. It talks to a Python service I run beside the app. The model only gets tools when the message looks like a data request.

01

You ask in the app

A question is typed in the chat, for example whether the market is open or who reports earnings today.

02

The screen posts it

The React Native client sends the message to the agent’s /agent/chat endpoint and waits for a text reply.

03

Tools run if needed

Greetings are answered directly. Data questions can call market status, stock search, earnings, news, or a web search.

04

A reply comes back

Tool output is trimmed, the model writes a short answer, and the chat screen renders it as Markdown.

You are “Market Lantern AI”, a professional financial assistant for Market Lantern customers. Speak directly to the user. Be helpful, polite, and professional. Do not output internal monologue. Use tools only when needed for data.

System prompt, from the project
Architecture

The path from a chat bubble to a fact.

I kept the agent outside the mobile app so the tool loop could stay in Python. The tools read from the same Convex backend that already serves the screens, rather than inventing a second data path.

Internal service URLs and keys are omitted from this page.
